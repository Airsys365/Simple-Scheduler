# Прога менеджера на базе GridMaster — Дизайн-документ

Документ описывает проработанный дизайн до написания кода. Всё, что зафиксировано
ниже, — результат серии решений. Открытые вопросы вынесены в отдельный раздел.

---

## 1. Бизнес-проблема (зачем всё это)

Начальник производства жалуется: менеджеры считают заказы плохо и **продают
часть заказов почти по себестоимости**, хотя клиент заплатил бы нормальную цену.
Причина — расчёт сложный, делается вручную/на глаз, маржа теряется.

**Главная ценность прогы:** не просто посчитать себестоимость (это GridMaster
уже умеет), а **подсказать менеджеру нормальную цену клиенту** и не дать продать
в минус по марже.

---

## 2. Архитектура

Выбрано: **отдельная прога менеджера + общий модуль расчёта**.

```
              ┌─────────────────────────┐
              │   Прога менеджера (UI)   │
              │  чертёж → проверка → €   │
              └────────────┬────────────┘
                           │ вызывает
                           ▼
              ┌─────────────────────────┐
              │   gridmaster_core        │  ← чистый модуль, без UI
              │   рассчитать(Заказ)→Рез  │
              └────────────┬────────────┘
                           │ тот же модуль зовёт
                           ▼
              ┌─────────────────────────┐
              │  Существующий GridMaster │
              │  (Tkinter десктоп)       │
              └─────────────────────────┘
```

Один модуль расчёта — два потребителя. Формулы не дублируются.

---

## 3. Реальное состояние кода (текущее)

**Статус:** Фаза 0–1 завершена. Код рефакторизован из монолита в модульную архитектуру.

**История:**
- `Grid_Master_V50.py` — **устаревший монолит**: 2568 строк, один класс, расчёт сросся с UI.
- **Текущее состояние** — 8 модулей с чёткой разделением:

```
gridmaster_core.py   ← чистый расчётный движок (Order → OrderResult)
├── calculate()      ← себестоимость и состав
├── calc_work_hours() ← формула трудозатрат
└── cutting_run()    ← раскрой и упаковка матов

manager_app.py      ← UI (CustomTkinter, 4 экрана)
ai_recognizer.py    ← Claude Vision: PDF → позиции
spec_reader.py      ← парсинг спецификации
pdf_export.py       ← генерация PDF-офиерты
price_manager.py    ← управление конфигом и ценами
steps_core.py       ← расчёт ступеней
steps_app.py        ← UI Steps Master
```

**Ключевое:** все расчёты в `gridmaster_core.py` без импортов UI. Можно использовать как библиотеку.

## 4. Рабочий процесс менеджера

```
Новый заказ
   │
   ▼
Загрузить чертежи (PDF/DWG, можно несколько)
   │
   ▼
Claude API: чертёж → структура «Заказ» (много позиций)
   │
   ▼
Менеджер ПРОВЕРЯЕТ и подтверждает каждую позицию   ← обязательный шаг
   │  (AI не уверен → жёлтая пометка; не смог → ручной ввод)
   ▼
Расчёт через gridmaster_core
   │
   ▼
Результат: себестоимость + РЕКОМЕНДУЕМАЯ цена (ползунок маржи)
   │
   ▼
Вывод: PDF клиенту · лист списания складу · сохранить в историю
```

---

## 5. Зафиксированные решения

| Тема | Решение |
|---|---|
| Структура заказа | Один заказ = **много позиций** |
| Доверие к AI | Менеджер **обязательно проверяет** и подтверждает извлечённое |
| Вывод | Цена + лист списания складу + сохранение в историю |
| Нет на складе | Считать по **последней цене** + поле «цена поставщика» для уточнения |
| Источник цен | **Пока не решён** — модуль цен проектировать гибко (см. раздел 8) |
| История | **Локально у каждого** менеджера (не централизованно) |
| Защита маржи | **Ползунок маржи**: по умолчанию на рекомендованной (мин. +X%), менеджер видит как едет цена клиенту |
| AI не смог | **Ручной ввод как fallback** — та же форма позиции, прога всегда работает |
| Показ чертежа | PDF — рядом с формой; DWG — рендер нетривиален, возможно только ручной fallback |

## 7. План фаз и статус реализации

| Фаза | Что | Статус |
|---|---|---|
| **0. Фундамент** | Извлечь расчёт из Tkinter в чистый `gridmaster_core.py`. Вход: `Order`, выход: `OrderResult` (себестоимость + лист списания). Формулы не изменены. | ✅ **ЗАВЕРШЕНА** — все расчёты в `gridmaster_core.py` без UI импортов |
| **1. Распознавание** | Claude Vision: PDF → `Order` с позициями. Анализ обрамления по кромкам (`frame_mm`, `bumper_mm`, `frame_analysis`). Уверенность → визуальные пометки. | ✅ **ЗАВЕРШЕНА** — `ai_recognizer.py` (claude-opus-4-8 @ 150 DPI), анализ по краям реализован |
| **2. Прога менеджера** | 4 экрана: история → приём → проверка → результат. Ручной ввод fallback. Ползунок маржи. Экспорт PDF/Excel, раскрой. Steps Master модуль. | ✅ **ЗАВЕРШЕНА** — `manager_app.py`, все экраны, UI полностью функционален |
| **3. Цены и склад** | Реальный источник цен и наличия. Пока: память цен по типам (`type_prices` в конфиге) + ручное поле. Excel как источник данных о матах. | 🟡 **ЧАСТИЧНО** — память цен работает, нужно интегрировать реальный API наличия |

## 8. Вопросы и решения

| Вопрос | Статус | Решение |
|---|---|---|
| **Источник цен и наличия** | 🟡 Частично | Excel как основной источник, память цен по типам (`type_prices`), ручное поле для уточнения. Нужна интеграция с реальной системой (Infotek API или выгрузка). `price_manager.py` спроектирован как абстракция для смены источника. |
| **Показ DWG** | ✅ Решено | PDF показывается рядом с формой, DWG идёт через ручной fallback (нет встроенного рендера). |
| **Бюджет Claude API** | ✅ Решено | Использование `claude-opus-4-8` на 150 DPI. Регулировать DPI и размеры PDF при необходимости. |
| **Формула маржи** | ✅ Решено | Ползунок маржи от минимума до максимума % (настраивается). Менеджер видит цену в реальном времени. |
| **Анализ обрамления** | ✅ Решено | Claude анализирует каждую кромку отдельно: выноски, подписи, размеры. Возвращает `frame_mm`, `bumper_mm`, текстовое обоснование (`frame_analysis`). |

---

## 9. Принципы реализации

- Фаза 0 не меняет ни одной формулы. Только отделяет расчёт от UI. Критерий
  готовности — тесты тождества проходят на реальных заказах.
- Источник цен — за абстракцией, чтобы фаза 3 не переписывала фазу 2.
- Прога менеджера всегда работает: даже при полном отказе AI есть ручной ввод.
- Главный экран ценности — Экран 4: менеджер видит и себестоимость, и
  рекомендуемую цену клиенту.
